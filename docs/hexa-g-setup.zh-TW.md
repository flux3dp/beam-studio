# HEXA G（fhx2galvo）開發期使用說明

> **名稱**：程式碼與文件裡，`fhx2rf` 叫 **HEXA RF**、`fhx2galvo` 叫 **HEXA G**，需要同時指兩台時叫
> **HEXA 2 series**。兩台共用的東西不少（相機世代、校正流程、透視格點的形式），但相機視野、工作範圍、
> 模組頭全都不同 —— 用一個名字統稱的結果就是把一台的參數套到另一台身上，開發期間已經發生過：HEXA G 的
> 透視格點一度被寫進共用路徑，HEXA RF 因為相機一律斜向，會整個吃到那組值。

這台機器還在導入，Beam Studio 裡與它相關的東西分成三類：**正式功能**（會留到上線）、
**開發期鷹架**（上線前會刪掉）、**還沒有設定入口的寫死值**（要量測）。這份文件是操作流程；
每一個設定項的入口、保存位置、預設值與是否需要量測，列在
[`hexa-g-settings.zh-TW.csv`](./hexa-g-settings.zh-TW.csv)。

---

## 1. 開啟機型與開發功能

兩個旗標，在 devtools 的 console 設定，**互不依賴**：

```js
localStorage['fhx2galvo-enable'] = 'true'; // 機型本身：機型清單與初始設定精靈看得到 HEXA G
localStorage['fhx2galvo-dev'] = 'true'; // 開發期鷹架（下面標「需 dev 旗標」的東西）
```

`fhx2galvo-dev` 打開後才會有：

- 頂列的 **燒瓶圖示 → 振鏡開發者設定**
- 振鏡設定裡的 **軸向**、**開發說明**、**Manual** 三個區塊
- 選擇機器按鈕的**斷線提示**
- 連線時**主動抓取機器上的移動範圍並覆寫畫布邊界**
- 相機校正裡的**【預覽雕刻範圍】**按鈕（第 9 節）

## 2. 選機型與文件設定

**文件設定**

| 項目 | 說明 |
| --- | --- |
| 機型 | 選 HEXA G。畫布固定 **920 × 520 mm** |
| Mopa 振鏡 | 有沒有裝 Mopa 模組頭。**它同時決定畫布邊界** —— 停泊在機器上的頭會占掉龍門行程，與這份工作用不用得到那顆頭無關 |
| 顯示重疊工作範圍 | HEXA G 文件決定（其他機型看的是偏好設定裡的同名選項），預設開啟 |

自動送料、曲面雕刻、貫穿加工對 HEXA G **一律關閉**。

## 3. 先連一次機器

**選擇機器**按鈕在機器名稱後面出現 <kbd>⛓️‍💥</kbd> 斷線圖示時，表示「畫面上那些來自機器的設定，
這個 session 沒有真的跟機器同步過」。開發期間 Beam Studio 的預設值和機器上的值經常不一致
（場鏡尺寸、模組偏移、移動範圍都存在機器上），所以看到這個圖示就先點一下按鈕重新連線。

連上之後會一次抓齊：`galvo_work_range`、兩顆頭的振鏡設定、`toolhead_shift`，並重畫邊界。

- 選過的機器會留到下次開啟，但**留下來的只是名字** —— 重整畫面後圖示會再出現，這是正常的。
- 這個圖示是鷹架（需 dev 旗標），上線前會移除。

## 4. 設定兩顆振鏡頭

入口：**機器選單 → 振鏡設定（CO2 振鏡）／振鏡設定（Mopa 振鏡）**，每顆頭一份，
存在機器上（`galvo_co2` / `galvo_mopa`）。

建議順序：

1. **場鏡尺寸** —— 70 或 110 mm，要和實際裝的鏡頭一致。它決定振鏡往兩側各可達多遠、區塊大小，
   以及圖案需不需要分割，所以填錯的話後面全部都不對。
2. **軸向**（需 dev 旗標）—— 這是機構安裝方式而不是校正值：CO2 兩軸都反向，Mopa 都不反。
   機構沒改就不用動。
3. **鏡頭參數** —— 畸變校正：scale / bulge / skew / trapezoid，X、Y 各一組。預設是中性值
   （100 / 1 / 1 / 1），代表「不做修正」，不是量測值。
4. **模組偏移** —— 鏡頭相對於龍門定位點的位置，寫到機器的 `toolhead_shift`。
   分塊是以主雷射頭座標系劃分的，這個值會改變圖案落在哪一格。

沒有紅光區塊：HEXA G 的紅光與雷射同軸，沒有東西要校正。

### 對話框下方的按鈕

- **預覽** 是紅光走框，功率固定 0；**標記** 會真的出光，用「標記參數」的功率與速度。
- 兩個按鈕都**自帶串聯**，不必先自己串一次。已在串聯狀態時再下一次串聯指令不會造成額外移動。
- 按鈕送出的是**畫面上當下的數值**，不需要先按儲存。要留在機器上才需要按儲存。
- **Manual 區塊**（需 dev 旗標）：串聯／解聯／Move／Dot 行為測試按鈕，以及只影響預覽的四個參數
  （步距、跳躍速度、跳躍延遲、圈數）。**留空就是用機器端的預設**。
- 板卡有個已知問題：場鏡參數改變後，跳到**同一個座標**不會真的移動。Move 會自己先跳一個
  差 0.1 mm 的位置再跳正確位置，不用手動繞。

## 5. 移動範圍與分塊參數

入口：**頂列燒瓶圖示 → 振鏡開發者設定**（需 dev 旗標，且文件機型是 HEXA G）。五組：

| 分組 | 內容 | 保存位置 |
| --- | --- | --- |
| 目前生效 | 場鏡尺寸、模組偏移（唯讀，要改去振鏡設定） | 機器 |
| 移動範圍 | 無 Mopa／有 Mopa 各一組 Min / Max | **Max 在機器**（`galvo_work_range`），**Min 只在這台電腦** |
| 分塊 | 區塊大小、龍門移動速度、list 指令上限、debug 圖 | 本機，匯出時送進 fcode |
| 接縫混合 | 重疊帶寬度、密度曲線、接縫策略、重疊帶打點的一整組 | 同上 |
| List 前置指令 | 跳躍速度、各種延遲、待機脈衝、Mopa 脈衝寬度 | 同上 |

**X 會再扣 30 mm 安全距離。** 機器報的 `galvo_work_range` X 是樂觀值 —— 皮帶驅動的 X 軸撞極限會回彈，
停泊的模組頭實際位置比那個數字再偏左一些，每次還不一樣。所以 Beam Studio 一律用「讀到的值 − 30」當右側
可到位置：畫布邊界、框選四角、相機拍攝位置全部跟著縮。對話框裡顯示與寫回機器的仍是機器的原始值。

## 6. 畫圖：模組切換與圖層參數

切換模組頭在**右側圖層面板的「模組」欄**，和其他多模組機型同一個慣例。切過去會套用該模組的預設：
CO2 振鏡 32 kHz / 1000 mm/s，Mopa 25 kHz / 350 ns / 1000 mm/s。

## 7. 匯出與路徑預覽

路徑預覽對振鏡內容的處理：標記是切割線、跳躍是移動線、打點是一格一格的點陣。

## 8. 框選預覽（走紅光）

HEXA G 的框選**一定會先解聯**：紅光跟著雷射路徑走，頭還串著的話紅光是從振鏡出來的，落點完全不對。
所以按下框選後可能會先等幾十秒（已經是解聯狀態時會跳過機械動作）。

框選的四角會被限縮到龍門走得到的範圍內，被拉回時會顯示「有物件超出可外框預覽範圍」。

Phase 2 可以討論如何處理振鏡外框預覽（小範圍 & 大範圍）。

## 9. 相機

**只做過簡單測試。** 相機世代與整個校正流程和 HEXA RF 相同，但**參數全部是 HEXA G 自己的**：校正圖樣、
拍攝位置、對位點、透視格點都分開了。共用的只有流程本身 —— 三台機器（Beambox II、HEXA RF、HEXA G）的差異
集中在 `LaserHeadFisheyeCalibration.tsx` 最上方一張表裡。

校正前會**先解聯**：拍板子那步要用紅光對位、雕圖樣要走噴嘴，兩者在串聯狀態下都是從振鏡出光。棋盤格步驟、
雕刻、預覽外框三個地方各問一次（已解聯時只花一次來回）。

已經處理的兩件事：

- 龍門掛著振鏡頭（串聯）時，目前不會特意做解聯動作，而是將相機移動降速到 `galvo_ts`，命令速度與等待時間估算兩邊都降。
- 拍攝位置一樣限縮在龍門行程內。游標上的虛線框走同一條路，所以**拍不到的那條右側區域在移動滑鼠時
  就看得出來**，不是拍完才發現。

校正圖樣是 HEXA G 自己的一組（HEXA RF 仍用原本的 `hx2-calibration.fc`）：`fcode/hexa-g-calibration.fc` 把 8 個 Ø0.5 mm 的點打在
**x 200–420、y 200–300**（220 × 100 mm，A4 橫放放得下），頭停在 `cameraCenter [440, 180]` 拍它們。
三者要一起動：那份 fcode、`cameraCenter`、以及 `hx2GalvoPnPPoints`（同一組點、改成相對頭部）。
圖樣比 Beambox II 的大一倍，因為噴嘴會擋住視野右側，圖樣必須往左伸才會落在剩下的視野中央 ——
第一版沿用 BB2 的 120 × 80 mm，導致視野左側 130 mm 完全沒有控制點，那就是當時左側變形的來源。

擺紙那步有個**【預覽雕刻範圍】**按鈕（需 `fhx2galvo-dev`）：解聯後沿上面那個矩形走一圈，方便對位。
進度條可以取消，但 raw move 送出去收不回來，所以是走到下一個角才停。

**release gate**：這組點該不該放在工作範圍的這個位置還沒定案。沒有【預覽雕刻範圍】的使用者沒有任何
參照物可以對齊白紙，所以圖樣可能要移到某個角落、或是加一個印出來的外框。正式 fcode 定案前要決定。

還沒處理：920 × 520 的廣角三件組（機器海運中）、斜向相機假設。

## 10. 遇到「串聯沒反應」

串聯／解聯／預覽／標記全都走 `control_task`，需要 fluxghost 與 fluxclient 認得這個 task。
- 桌面版：ghost 隨 app 打包，更新 Beam Studio。若真的遇到這個問題，檢查一下是都連到錯誤的 host/port。
